## Two colours, seven-term arithmetic progressions

The benchmark uses two colours and progression length seven. It calls this W(7,2); sources using colour-first notation call it W(2,7). A valid colouring of length 3703 proves W > 3703. The target is length at least 3704.

Monroe's current journal article, *New lower bounds for Van der Waerden numbers using distributed computing*, lists length-seven/two-colour bound >3703 and prime 617 for its construction. This is the same numerical bound as the brief, not evidence of a colouring longer than 3703. Rabung and Lotts compile the bound; the underlying residue construction predates their paper.

- https://combinatorialpress.com/jcmcc-articles/volume-128/new-lower-bounds-for-van-der-waerden-numbers-using-distributed-computing/
- https://arxiv.org/abs/1603.03301
- https://doi.org/10.37236/2363

Queries included `van der Waerden W(2,7) lower bound 3703 2025 2026 Rabung Lotts`, and `"van der Waerden" "3704" arxiv`. No newer explicit construction was located. This is a literature search finding, not a proof that none exists.

## Binary code

Brouwer's live general binary code table lists A(21,10) in the interval 42-47. It attributes the lower bound to Kaikkonen, IEEE Transactions on Information Theory 35 (1989), page 1344. Gijswijt, Mittelmann and Schrijver establish the upper bound 47. Neither a new lower bound nor a claim of 43 codewords was located.

- https://aeb.win.tue.nl/codes/binary-1.html
- https://doi.org/10.1109/18.45298
- https://arxiv.org/abs/1005.4959

Queries included `"A(21,10)" Kaikkonen construction code 42`, `"A(21, 10)" "43"`, and `"A(21,10)" arxiv 2026 2025`. The identity A(n-1,2e-1)=A(n,2e), stated on Brouwer's page, relates A(20,9) and A(21,10). The extra even-weight coordinate view is useful for search but does not identify all unrestricted length-22 codes with this problem.

Baseline reconstruction reference: Brouwer, Shearer, Sloane and Smith, *A New Table of Constant Weight Codes*, Table II and key 18, describes the 42-word construction as extended quasi-cyclic: https://neilsloane.com/doc/Me153.pdf. The original IEEE article could not be retrieved. On resumption, curl received an HTTP 202 CloudFront web challenge; the response headers are saved in sources/kaikkonen_resume_headers.txt. Python urllib also encountered a local certificate validation failure. Metadata from Crossref, OpenAlex and Semantic Scholar is saved under sources/. The local record-score reconstruction uses the stated family; it does not assert isomorphism to the original certificate.

The unrestricted A(22,10) even-weight problem is not equivalent to A(21,10): the live table gives A(22,10) >= 64. To use length 22 as the same search problem, an added coordinate must remain fixed; puncturing that coordinate then preserves distance. Exact parameters of the saved length-20, length-21 and fixed-zero length-22 views are in logs/code_views.jsonl. This qualification prevents treating a larger length-22 code as a length-21 record.

## Methods

A cyclic search also tests prime periods above 617. It identifies positions by discrete-logarithm classes, forbids monochromatic cyclic seven-term progressions, and uses exact SAT. A period above 617 has no zero-step seven-term repetition inside length 3704. The short probe selects families for a longer focused prime-619 run.

The progression search uses full CNF constraints for all seven-term progressions. Each progression gives a positive and a negative clause. The solver logs report the actual clause count. Glucose and MiniSat preserve learned state across interrupted timed slices in the same process. Disk checkpoints save phases, statistics and seeds, not learned clauses. A neighborhood solver initially frees windows and random variables; later batches also free variables from UNSAT assumption cores. C++ local searches maintain exact AP counts, use a ProbSAT-style break penalty, restart from their best checkpoint, and in later batches use tabu penalties. The resumed weighted variant increases integer penalties on violated progressions to leave recurring basins. On normal completion it independently recomputes every AP count and weighted break/make counter and asserts agreement. Its bounded probe output is included in the run table. A later optional diversity run samples one-violation ties and saves those with greater Hamming distance from its initial checkpoint, while leaving the submitted valid certificate unchanged. The closest coloring found is independently checked before any claim.

The length-22 view is used with an added fixed-zero coordinate; unrestricted even-weight A(22,10) is a different problem, as STATUS.md explains. The binary-code methods use A(20,9), then add even parity to obtain the required A(21,10) certificate. Direct tabu and annealing searches optimize a 43-word candidate's exact squared distance deficits. The prepared row-level diversification mode also freezes recently moved rows; it is motivated by the saved star-conflict diagnostic, and its use is recorded in the batch commands. Large-neighborhood search removes words from a valid code, enumerates compatible words from the complete length-20 cube, then solves a clique repair problem with greedy-coloring bounds and timed exact backtracking. Candidate sets above 15000 are skipped. Growth searches are bounded to 30 seconds and equal-size repairs to 5 seconds; successful growth is retained before any equal-size move. It saves the actual valid working code after each repair and resumes that code in subsequent batches. A guided variant can start from a smaller verified subset, retain a chosen anchor word, and grow one word at a time. The later guided phase refines the default deletion range of 8..29 to 1..29 so it also tries small repairs of its smaller seed. The conflict-graph diagnostic extracts both a maximum valid subset and a valid subset that retains a problematic word; all such seeds are independently checked before use. An independent exhaustive-subset check validates the clique routine on the saved test cases. Another exact orbit search tests zero plus six seven-word orbits under three simultaneous seven-cycles. It uses independent rotations and block permutations to reduce choices for the first orbit. The additional five-cycle search uses four simultaneous cycles at length twenty, three fixed words and eight full orbits, for a total of forty-three words before parity extension. It tests fixed block-pattern sets 0/3/5, 0/3/12 and 0/3/13. An additional case uses all eight even-parity four-bit fixed block patterns and seven full orbits, again totaling forty-three words. Its fixed-word distance and target orbit count are checked by the actual binary. Completed first-orbit roots and pending roots are checkpointed, so subsequent seeds do not repeat roots already exhausted. Only independent block rotations and permutations preserving the chosen fixed-word set are used to restrict the first orbit. A completed restricted-family search would not prove global nonexistence. Full SAT also encodes a 43-word length-20 distance-nine code with XOR variables and exact cardinalities. Translation, coordinate permutation and row sorting remove symmetry. The SAT phase initializer can normalize the best saved 43-word near-code while preserving every pairwise distance. The column-order option also orders coordinate columns inside the two blocks preserved by the fixed distance-nine pair. A lexicographically least row-major representative satisfies both row and column orders, so this option preserves existence. Its encoding was checked against exhaustive Boolean truth tables, and its small-matrix normalization was checked independently; actual output follows below. The later SAT repair phase fixes a clean distance-nine pair, disables row and column ordering, and bounds the total number of changed bits around the saved normalized near-code. Its negative results apply only to that Hamming ball with those two words fixed. The signed-literal cardinality helper was checked exhaustively against direct Hamming distances. The fixed distance-nine pair is justified because Brouwer's table gives A(20,10)=40, so any hypothetical 43-word code must contain such a pair.

An additional exact small-trade search fixes a verified 42-word code, assigns every word of the complete length-20 cube a mask of old words it conflicts with, and enumerates deletion sets. For a deletion set D, the union of conflict buckets indexed by subsets of D is exactly the set compatible with every retained word. An exact clique search asks for |D|+1 replacement words. The checkpoint stores the complete ordered seed and the next unresolved deletion set, so interrupted sets are repeated rather than silently discarded. A candidate cap stops the search explicitly as incomplete. Completed deletion radii apply only to that specific seed and do not establish global optimality. The separate direct-extension probes each examined the entire cube: the baseline seed's minimum squared extra-word deficit was 10 and the hybrid seed's was 4. Thus both saved codes are maximal for adding one word without changing existing words; this does not rule out a larger code. Raw probe output is in the measured table.

The completed hybrid-seed trade pass is audited against the exact binomial count in logs/code_trade_coverage_verification.json. The final checkpoint and the logged count agree on all deletion sets through radius seven. This is a local negative result for the immutable seed in checkpoints/code_trades_initial42.txt. A second trade pass uses the original record-score seed; its completion status is reported separately in the run table. A later annealing pass starts from the best saved near-code instead of the original cold initialization.

Baseline reconstruction probes are in logs/reconstruct42.log and logs/reconstruct42_half.log. The zero/all-ones fixed-word restriction failed; using fixed word 1023 yielded the submitted record-score seed. These probes reconstruct the baseline, before the code-improvement search.
