## Tools: built versus reused, licences

`make tools` builds the compiled programs with Clang:

| Tool | Implementation and reuse | Licence |
| --- | --- | --- |
| `build/fast_sim` | New C++ simulator with expanding byte tape, halting step, head/state, exact RLE tape output and sampled statistics | MIT, `tools/LICENSE` |
| `build/reference_sim` | Ligocki's C++ parser and simulator, with a small JSON adapter. Only the initial/growth allocation size is tuned; transition execution is unchanged. Independent of the fast simulator's transition/tape code | [sligocki/busy-beaver](https://github.com/sligocki/busy-beaver), MIT; archived snapshot directory `614ba83` |
| `build/decider_tc` | Original Ligocki translated-cycler/linear-recurrence search, built with its original tape allocation and adapted to emit replay parameters as JSON | Same MIT source |
| `tools/ngram.py` | Calls bbchallenge's upstream n-gram CPS search and serializes its printed local-context/language certificate; the search is not reimplemented | [bbchallenge-deciders](https://github.com/bbchallenge/bbchallenge-deciders), Apache-2.0 OR MIT; archived snapshot directory `abcf537` |
| `tools/check_tc.py`, `tools/check_ngram.py` | New small independent Python checkers; neither imports or shares searcher code | MIT |

The bbchallenge program-output licence is CC-BY-4.0; its licence texts are retained. The BB6 busycoq snapshot (`c421dd9`) is a research/status source, not a compiled dependency; its MIT and LibTactics licence files remain in the archive/vendor tree. The wiki identifies its content as Creative Commons Attribution. Google DeepMind's repository states Apache-2.0 for software and CC-BY for other materials; no code from it is used in the tools. [data/SOURCES.md](data/SOURCES.md) supplies the exact archive hashes.

Both deciders emit checkable certificates. Translated-cycler certificates contain the machine, anchor, positive period and displacement; the checker replays on a sparse tape and verifies the required half-tape or visited-interval equality. CPS certificates contain left/right languages and local contexts; the checker verifies blank inclusion, absence of halting contexts, and exhaustive successor closure. See [tools/CERTIFICATES.md](tools/CERTIFICATES.md). The checkers reject Python optimized mode because their obligations use assertions.

Both simulator conventions count the halt transition, and complete `---` as `1RZ`. The fast simulator's tape-file argument writes absolute start, symbol and run length, with zeros outside the described region. Width is the head span including the final position. The positional hash is an additional comparison aid, not a proof certificate.

The classifier first checks a stable small span, then high spatial complexity, then predominantly translating growth, then a strongly compressible tape with repeated turns; the remainder is called counter-like. ## Risks

- **Resource-control deviation:** an intermediate `make verify` rerun overlapped the four-worker triage. Two four-worker pools could schedule eight CPU children, so the requested six-core limit was not enforced during that overlap; actual physical-core utilization was not measured. The final verification was run sequentially after triage. A shared four-child lock gate is now used by verification and triage, leaving room for their Python coordinators. This fixes future enforcement but does not erase the earlier lapse. No individual command approached the two-hour ceiling.
- **Status incompleteness:** the published list, wiki prose, sheet and current proof branch are not synchronized. Later public claims are excluded conservatively without rebuilding their proof-assistant developments. Private Discord reservations or unannounced results may still exist. Recheck exact target strings and equivalence classes before next-stage work.
- **Conservative exclusions:** the broader paper list and shared-table rule intentionally overexclude. Different start states are not treated as proved-equivalent blank orbits.
- **Bounded experiments:** finite direct simulation and compressibility cannot establish non-halting, a stable macro system or absence of chaos. These holdouts already received substantial community computation; the direct run is a reproducible baseline, not evidence of a new advance.
- **Trust boundary:** independent executable checkers and known-halter gates substantially reduce implementation risk, but their general soundness has not been formalized here. The certificate regression set is from the published smaller domain; target-domain simulator testing does not constitute exhaustive decider validation.
- **Next-stage uncertainty:** proposed sweep/counter/list rules still need discovery, proof and an independent certificate checker. A proposed acceleration may eventually reveal halting rather than non-halting. No new decision should be inferred from the shortlist.

No commits were made and nothing was posted online. Reproduction commands and artifact roles are in [README.md](README.md).
