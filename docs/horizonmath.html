HorizonMath checks and negative results

By Hari Naralasetty (GitHub · LinkedIn)

No new record in any of the committed batches.

Record-status gate

Batch A retained DTS scope 112 and constant-weight code size 36. Batch B retained a covering with 30 blocks and a Schur coloring through 536. These are reproduced published constructions, not new sprint records.

The covering repository web entry could not be fetched. Batch B subsequently checked the maintainer's downloadable metadata and latest archive, which confirm a 30-block construction and lower bound 28. The Schur convention here is the largest colorable integer. A different smallest-uncolorable convention must not be read as an improvement.

Strict independent verification

The DTS verifier computes exact positive differences and requires global distinctness. The constant-weight verifier computes pairwise Hamming distances. The covering verifier checks every required subset. The Schur verifier checks integer sums, including doubling. Each derives its score from the construction and ignores claimed scores.

Benchmark checker observations

The status review identified boundary tolerances that can admit points outside the intended square or off the unit sphere, producing apparent floating-point gains. Approximate moment tests also do not establish an exact spherical design. These are observations about acceptance rules, not mathematical record improvements, and the sprint did not count them as results.

A separate Schur format mismatch was reproduced. The prompt requests a coloring object, while the benchmark validator accepts a bare list and rejects the wrapper. The published coloring passes in the accepted format and remains independently checked for its mathematical property.

Search effort and negative results

Batch A used CP-SAT, orbit models, neighborhood repair and tabu search. Its committed report discloses a campaign shorter than requested. For example, a code tabu run made 281591612 iterations in 600.001 seconds and ended with collision energy 1, an invalid near miss. A DTS run ended at collision energy 2 after 281303682 iterations in 600.000 seconds.

Batch B records covering wall time 14758.238 seconds and Schur wall time 14919.003 seconds. CP-SAT, SAT neighborhoods, weighted tabu search and restricted orbit/link models found no record. The saved covering near misses leave 3 subsets uncovered; Schur near misses retain 1 violation. Neither is a valid improvement. Timeouts and restricted infeasibility results do not prove the unrestricted problem unsatisfiable.

Final batch C outcome

The W(7,2) search retained a two-colour construction of length 3703 with no monochromatic seven-term arithmetic progression. The binary A(21,10) search retained 42 codewords with minimum distance 10. Both match the published lower bounds; neither is a new record. Colour-first sources write the progression problem as W(2,7). A valid length-3703 colouring proves W > 3703, not the existence of a length-3704 colouring.

The code is a reconstruction in the published quasi-cyclic family with the published parameters. Isomorphism to the original certificate was not proved. The independent verifiers check every progression step or every pairwise distance using exact integers, and derive scores from the constructions.

Credited active wall time was 14675.648 seconds for progression search and 14610.090 seconds for code improvement search, excluding interruption gaps. SAT, local search, clique repair and restricted orbit searches found no valid improvement. Saved length-3704 colourings still have 1 progression violation; a code near miss has squared distance-deficit energy 4. These invalid candidates do not establish a new bound.

The source status review links Monroe's van der Waerden bound compilation, Brouwer's binary code table and Kaikkonen's code construction reference. Papers and downloaded source pages are linked, not copied here.

Scope and reproduction

All committed batches are included. Run make -C horizonmath verify for the distributed exact positive and negative checks. The original source targets also compare against upstream benchmark validators; those external implementations are not vendored here.
