How to check the results yourself

By Hari Naralasetty (GitHub · LinkedIn) · 2026-10-22

Every reported result has a source artifact and an executable check.

Run from the repository root

make verify-site
make verify-math

Site verification checks imported hashes, b-file equality against the adjacent source workspace, HTML structure, internal links, metadata, sitemap coverage, JSON-LD and the privacy scan. Mathematical verification runs the OEIS extensions with both methods, BB(6) local proofs and HorizonMath exact construction checks.

Python and a C++ compiler are required for mathematical recomputation. Building the site also requires Git and the repository history for content dates, plus Pillow for its results-table image. The validator uses lxml. The full site provenance check additionally needs the pinned sibling source workspaces; mathematical verification uses the files distributed in this repository. No browser-side framework, external font, tracker or runtime script is used.

Check scope

The OEIS full check recomputes the extended ranges. A separate quick command checks only published overlap. Recorded source timings are historical measurements, not promises about another machine. BB(6) portable verification checks local claims and an empty decision registry; the full simulator campaign remains in the source workspace. HorizonMath portable verification checks the exact mathematical conditions, with invalid controls.

Source snapshots

Provenance and numeric claim ledger, b-file hashes, and the import manifest pin the evidence. Run python3 tools/import_sources.py only when deliberately refreshing sources, then rebuild and rerun all checks. It reads committed source blobs and never copies third-party code.

Local report

Read actual verification output. Publication, submission to OEIS and source refreshes remain separate owner actions.
